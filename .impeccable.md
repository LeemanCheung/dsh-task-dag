## Design Context

### Users

DeepSeek Harness developers and technical operators use this plugin while supervising active multi-agent work. They need to scan ownership, blockers, execution state, workflow grouping, and peer communication quickly, then open the relevant Session without leaving the graph.

### Brand Personality

Precise, energetic, trustworthy. The interface should feel like a focused orchestration console that belongs inside DSH, not a generic diagram editor or decorative dashboard.

### Aesthetic Direction

Use a high-information technical control surface with stronger category distinction than the current graph. Preserve DSH semantic theme tokens and light/dark compatibility; use purposeful edge styles, compact labels, and restrained state color. Avoid decorative gradients, glow-heavy dark UI, oversized cards, and motion that does not explain state.

### Design Principles

1. Make topology and edge meaning readable before adding decoration.
2. Distinguish state with text, symbols, and line style as well as color.
3. Progressively disclose detail: overview first, focused Team and Workflow views next, message content only on demand.
4. Preserve deterministic layout, direct Session navigation, keyboard access, and reduced-motion behavior.
5. Keep the visualization read-only and projection-driven, with no polling or parallel persistence.
